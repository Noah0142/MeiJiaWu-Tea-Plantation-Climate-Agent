> 这一版按**配音员的口吻**写: 短句、口语连接、每段结尾都落在一个人会自然停顿的地方;
> 按**产品发布片的口气**写: 先讲痛点和场景,再给能力,最后落到"你能得到什么"。

**00:00–00:12** —— 像跟人开个头,语速慢一点,"能差上七天"后面停半拍

杭州西湖,梅家坞。同一座山,两处茶园的采摘期能差上七天——而霜冻最狠的那几个小时,又常常在凌晨。我们想做的,就是把这件事算清楚。

**00:12–00:27** —— 转成"带你用一遍"的口气;三项一口气念完,不要一个个断

打开网页,先是一块实时大盘:现在多少度、湿度多少、今晚最低会降到几度,一眼看完。未来三天的逐小时气温,给的不是一个数,是一个区间——P10 到 P90。遇上霜冻、高温,它还会分等级提醒你。

**00:27–00:39** —— 放松、带点笑意;"问一句就行"轻快

拿不准的时候,问一句就行。助手的回答不是随口说的:同一份预报、同一套风险结论。它说的温度,和那条线上是同一个数。

**00:39–00:56** —— 这一段是产品的主角,语速稳住;"再点一下"后面短停,让结果落地

山里,地形最要紧——同一片云,落在不同的坡上就不一样。地图上点出你的地块,30 米地形马上算出海拔、坡度和坡向;再点一下,春季积温、六年累计霜冻、什么时候开采,全都有了。六张图层叠上去,地块和地块,直接比。

**00:56–01:14** —— 这一段说数字,慢下来;"没见过的年份"和"1.52 度"重读

这些数,来自一个学过七十多年天气的模型:ERA5-Land 再分析,配上 30 米地形和全国茶园分布,再用 LightGBM 分位数回归,直接给出区间。最狠的一次考试留在没见过的年份:平均误差 1.52 度,比"明天照今天"准四成。

**01:14–01:28** —— 回到轻松;最后一句是给用户看的画面,语气转暖

地里的传感器,随时能接进来——传一段实测,模型立刻用它校准。想看数据、想问问题,山上山下都行:手机上是同一套数据、同一个助手。

**01:28–01:40** —— 收尾,放慢,两句之间留一口气;"让气候可感知,让风险可预判"压低收

从一片山地,到每一块茶地;从气象数据,到一句"今天要不要上山"。梅家坞茶园微气候智能体:让气候可感知,让风险可预判。

## 这版改了什么(对着上一版看)

| 上一版(说明稿) | 这一版(人声 + 产品) |
|---|---|
| 「支撑这一切的预测模型是用真实数据练出来的」 | 「这些数,来自一个学过七十多年天气的模型」 |
| 「霜冻和高温另有分级提示」 | 「遇上霜冻、高温,它还会分等级**提醒你**」 |
| 「它说的温度,和你前面看到的是同一套数字」 | 「它说的温度,和**那条线上**是同一个数」 |
| 逐项报功能(海拔、坡度、坡向、TPI、土地覆盖…) | 只挑一个场景:「同一片云,落在不同的坡上就不一样」 |
| 指标五个都念 | 只留最有说服力的两个: **1.52 度 / 准四成** |
| 结尾罗列"数据、模型和应用连成链路" | 落到人话:「从气象数据,到一句'今天要不要上山'」 |

**人味**来自三件事: 短句 + 口语连接词("山里,地形最要紧"、"拿不准的时候");把书面语换成嘴上会说的话;每段的最后一个字都落在自然停顿上,不硬接下一段。
**产品感**来自三件事: 先痛点(采摘期差七天、霜冻在凌晨)再给能力;每个能力都问一句"你能得到什么";数字少而硬(1.52 度、准四成、七天)。

## 数字的出处

- 「采摘期能差上七天」: `/api/site/point` 两处真实茶园(云栖竹径 3/27 vs 梅家坞北坡 4/3,模型栅格多年值);
- 「P10 到 P90」「霜冻 / 高温分级」: `/api/forecast` 真实分位数与风险等级;
- 「春季积温 / 六年累计霜冻 / 什么时候开采」: `/api/site/predict` 对该地块的真实返回;
- 「1.52 度 / 准四成」: `docs/model_report.md` 测试集(2025-01~2026-10,训练全程未见,持续性预报对标 2.69 度);
- 「传感器接进来做校准」: `models/live_data.py` 的实测锚定 + `models/predict.py` 的偏差订正 LUT。

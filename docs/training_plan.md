## 1. 模型任务与总体思路

**任务**:输入"背景气象场 + 地形 + 邻站实况 + 近期实况",输出梅家坞茶园 0–72h 逐小时微气候 + 霜冻/高温热害风险概率。

**核心范式(御茶村同款):大背景 + 小订正 = 误差订正(MOS)**

- 训练时:把 ERA5-Land 再分析(9km)当"完美预报",目标 = **实况 − 格点值残差**;
- 运行时:数值预报(ECMWF Open Data 0.25° / OpenWeather / Open-Meteo)经滚动偏差订正后 + 模型残差 = 茶园尺度预报。
- 为什么学残差:残差映射比"绝对值映射"在**站点之间更可迁移**(锚点站校准新点位)、对背景场换源更稳健 —— 这是迁移学习的基础。

**明确边界**:不训气候大模型;紧凑降尺度模型 + LLM 交互外壳。参考项目同样用 LightGBM,证明这条路线在"传感器网络 + 微气候预报"场景已被验证。

## 2. 数据合同(团队要准备的)

### 2.1 最小集(两样)

| 文件 | 内容 | 说明 |
|---|---|---|
| `background.csv` | ERA5-Land 逐小时:`time, t2m, d2m, u10, v10, ssr, tp, stl1, swvl1, sp`,≥3 年(最少 1 年) | 训练输入。**加 3×3 格点**时周边格点列名加 `_cN` 后缀(`t2m_c2 ... t2m_c9`) |
| `labels.csv` | 同段逐小时实况:`time, obs_t2m, obs_rh, obs_ws, obs_wd` | 训练标签。**多站时各站加后缀**(`obs_t2m_s1, obs_t2m_s2 ...`) |

### 2.2 加分项
- `static.csv`(多站必填):`station, lat, lon, elevation_m, slope, aspect_deg, tpi, cai` —— 每站高程/坡向等;
- `events.csv`:`date, type` 历史霜冻/热害事件(验证预警);
- DEM(12.5/30m)用于空间场输出(后期)。

格式约定:北京时间整点 ISO8601;缺测留空;列名不一致只改 `config.yaml` 的 `columns` 映射。

## 3. 特征工程(已实现)

- 时间谐波(小时/年),冻害窗口(2–4 月)/热害窗口(7–8 月)
- 背景场诊断量(RH/风速/12h·24h 降水/日较差),气候距平(训练段气候态,防泄漏)
- **目标站实况滞后与滚动**(1–48h 滞后、24h Tmin/Tmax、近 24h 实况−背景偏差)
- **空间上下文**:周边格点 `bg_*_plus_h_cN` + 邻域均值/极小/极大(±t 与 ±t+h);邻站实况 `obs_t2m_nb*`(当前 + 24h 滞后)—— 多节点协同
- 静态地形:高程、坡度、坡向 sin/cos、TPI、冷空气汇集指数、海拔差
- 防泄漏:全部特征只用 t 时刻及以前信息;`bg_*_plus_h` 训练时=再分析 t+h 值(完美预报),运行时=数值预报

## 4. 样本构建与切分

- 时效 h ∈ {1,3,6,12,24,36,48,72},样本 (X(t), y(t+h));y = obs(t+h) − bg(t+h)(误差模式)
- **时间顺序切分**(如 2020–2024 训练 / 2025 验证),严禁随机切分
- 霜冻事件:日 Tmin ≤4℃(分级 2–4 轻 / 0–2 中 / <0 重);热害:日 Tmax ≥35℃ 或日均 ≥30℃

## 5. 模型路线(阶梯式,逐层验收)

| 层 | 模型 | 说明 | 验收 |
|---|---|---|---|
| L0 | 持续/递减率/背景场直用 | 地板 | 必须被打败 |
| L1a | **随机森林**(`--algo rf`) | 快速基线,特征重要度 | 数分钟出结果 |
| L1b | **LightGBM 分位数回归 P10/P50/P90** + 湿度 | 主力(与参考项目同族,升级为残差+分位数) | 24h Tmin ±2℃ 准确率显著高于背景场直用(对标 52%→64%) |
| L2 | LSTM / Crossformer-BiLSTM / CNN-LSTM | 数据 ≥2 年再上;CNN-LSTM 边缘版参考能耗/延迟收益 | 集成提分 |
| 空间场 | 地形协变量统计降尺度 | 茶园 30m 温度分布图(哪片坡先受冻) | 与 MODIS LST 相关 ≥0.8 |

**迁移学习(锚点站 + 稀疏校准)**:全站点预训练 → `--finetune-station S` 逐站微调(LightGBM init_model 续训)。新点位只需少量本地数据即可校准 —— 对应"传感器有限时用锚点站迁移"的建议,也匹配御茶村"少量站点校准全园偏差"的思路。

## 6. 评估标准(验收线, 含对标指标)

- 回归:分时效 MAE/RMSE,四季分季;skill vs 持续预报 ≥15%;
- **对标指标:24h 最低气温预报准确率(±1℃ / ±2℃)** —— 御茶村 52%→64%,我们以"背景场直用准确率"为起点,要求模型提升 ≥10 个百分点(自测合成数据:75%/100%);
- 预警:霜冻 POD ≥0.7、FAR ≤0.5(标准 P50 阈值;保守 P10 阈值单独报);
- 分位数校准:P10–P90 区间覆盖率接近 80% 且区间窄。

## 7. 运行时与部署(对接参考项目)

```
ECMWF Open Data 0.25° / OpenWeather API / Open-Meteo 预报(多格点)
  → 滚动偏差订正(近 48h 实况−背景) → LightGBM 残差模型
  → 茶园 0–72h 逐小时 T/RH + P10/P90 → 风险分级(risk.py)
  → LLM Agent → 茶农自然语言建议
```

**与 microclimate-sensor-network 集成的现成产物**:
- `scripts/export_to_js.py`:模型 → m2cgen 纯 JS(其上游项目同款做法),放进 Express 后端零 Python 运行;
- `models/infer.py --format sensor-network`:输出与其前端一致的 `[{ts, temperature, humidity, wind_speed, gust_speed, soil_moisture}]` schema;
- 输入侧:其 `WeatherForecast.ts` 已接 OpenWeather API 3.0 —— 可作为运行时背景场来源之一(备选 ECMWF Open Data,免注册且中国区免费)。

## 8. 传感器网络路线图(御茶村式,分两期)

- **一期(本 7 天)**:无硬件,全公开数据。杭州站 58457(NOAA ISD 免注册直下)+ ERA5-Land 多格点训练;演示用公开 API 模拟传感器流。
- **二期(赛后/拿到硬件后)**:按御茶村密度(水平 200m)在梅家坞选代表性地形布点——向阳坡、背阴洼地、谷底各至少 1 套 + 1 套垂直剖面(探测逆温/冷池)→ 用 `--finetune-station` 做锚点校准 → 模型即插即用;可参考 microclimate-sensor-network 的 RP2040 + 太阳能 + LoRa 网关方案,预报跑在边缘(m2cgen JS)。

## 9. 七天节奏(与数据获取并行)

- **D1** ✅ 数据合同 + 训练管线 + 误差订正/多格点/多站/微调 + 合成数据全链路自测
- **D2** 收第一批数据 → 对齐/质控/EDA(梅家坞气候态、3–4 月倒春寒频率)
- **D3** L0 基线 + RF 快筛特征 → LightGBM 误差订正首轮指标(24h Tmin 准确率对标)
- **D4** 运行时预报接入(ECMWF/OpenWeather)+ 滚动偏差订正 + 推理 + JS 导出
- **D5** LLM Agent + 农学知识库 + FastAPI;对接 sensor-network 后端(可选)
- **D6** Web 仪表盘(地图+曲线+风险卡片+对话)
- **D7** 案例回放(倒春寒事件)+ 评估报告 + 演示

## 10. 风险与决策点

- 茶园传感器数据 <1 年:杭州站长序列预训练 + 茶园数据微调(不走全量重训)
- 霜冻样本少:2–4 月窗口专项;概率输出而非硬分类
- 背景场换源(ERA5→预报)系统性偏差:运行时滚动偏差订正已实现,误差模式下进一步吸收
- 空间尺度最优性:用特征重要度 + 消融(单格点 vs 3×3 vs 邻站)在真实数据上验证,写进评估报告

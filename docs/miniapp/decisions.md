# 决策记录(小程序)

## D1 · 技术栈: 原生小程序, 不引第三方组件库

- 时间: 2026-10-14
- 决策: WXML/WXSS/JS 原生开发, 不引入 WeUI/TDesign/Vant; 图表自研 canvas 2d 组件。
- 理由: 页面元素简单(卡片/胶囊/曲线/地图), 原生足以实现高质量效果; 减少依赖与构建风险; 目标用户是团队自己部署维护。
- 备选: TDesign MiniProgram(功能多但引入成本高)、ec-canvas+ECharts(体积大, 且网页端已验证过 ECharts 的 oklch 悬停 bug, 不重复踩)。

## D2 · 视觉方向: 直接延续网页版设计令牌

- 时间: 2026-10-14
- 决策: 不做三套 UI 方案探索, 直接沿用网页版 oklch 令牌(换算为 sRGB)、衬线标题、卡片语言。
- 理由: 用户明确要求"延续网页风格, 不能挤在一团"; launch-wechat skill 规定已有品牌与用户指定风格优先。
- 产出: `docs/miniapp/design-system.md` + 高保真原型 `prototype/index.html`。

## D3 · 信息架构: 4 个 tab, 对话独立一级入口

- 时间: 2026-10-14
- 决策: 大盘 / 农事助手 / 地图选点 / 数据接入。
- 理由: 手机端"问一句"是最高频动作, 对话值得一级入口(与网页版把对话置顶一致); 数据接入是低频配置项, 放最后。

## D4 · 状态管理: 无全局 store, 页面级 + 本机缓存

- 时间: 2026-10-14
- 决策: 预报数据缓存于 `getApp().globalData.forecast`; 对话历史与 API 地址存 `wx.setStorageSync`。
- 理由: 规模小, 引入状态库是过度设计; 对话历史本机持久化提升体验(重进不丢)。

## D5 · 数据接入: 服务器地址可配置

- 时间: 2026-10-14
- 决策: `app.js` 提供默认地址, "数据接入"页可修改并存本机; 本地调试填 `http://127.0.0.1:8000`。
- 理由: 团队需要本地调后端 + 云端演示两种场景; 免改代码切换。

## D6 · 域名与审核: 演示用体验版 + 调试模式, 正式版需备案域名

- 时间: 2026-10-14
- 决策: 比赛演示走"体验版 + 手机打开调试"绕过域名校验; 正式发布需自备 ICP 备案域名(见部署教程末节)。
- 理由: 微信正式版强制 request 合法域名, Railway 域名无备案; 这是平台硬约束, 不可绕过。

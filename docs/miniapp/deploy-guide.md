# 微信小程序部署教程(从零开始, 一步步)

> 面向没有小程序经验的团队成员。只需按顺序做, 每步都有"完成标志"自查。
> 小程序代码在 `miniapp/` 目录; 后端已在 Railway 部署(https://github.com/Noah0142/MeiJiaWu-Tea-Plantation-Climate-Agent)。

---

## 总览: 一张图看懂全流程

```
① 注册小程序账号(拿 AppID)  ② 下载微信开发者工具  ③ 导入 miniapp 目录
        ↓                          ↓                       ↓
④ 填服务器地址(数据接入页)  ⑤ 本地调试跑通   ⑥ 上传代码 → 体验版(发二维码给团队)
        ↓
⑦ (可选)正式发布: 需备案域名 → 配置合法域名 → 提审 → 发布
```

比赛演示走到 **⑥ 体验版** 就够用; ⑦ 是产品化选项。

---

## 第一步: 注册小程序账号(约 15 分钟, 免费)

1. 电脑浏览器打开 **https://mp.weixin.qq.com** → 右上角「立即注册」→ 选择 **「小程序」**;
2. 用一个**没有注册过公众平台的邮箱**注册(QQ 邮箱即可), 设置密码;
3. 邮箱收验证邮件 → 点击链接激活;
4. 选择主体类型:
   - **个人主体**即可(免费、无需营业执照)。个人主体不能用部分类目(如电商交易), 但我们做的是"农业气象信息展示", 属可用范围;
5. 按提示填写身份证信息 + 用本人微信扫码验证(约 5 分钟);
6. 登录小程序后台 → 左侧「开发」→「开发管理」→「开发设置」→ **复制 AppID**()。
   > ⚠️ AppID 不是密码, 可以写在团队文档里; 但 **AppSecret 绝不能外传**(我们也不用它)。

**完成标志**: 拿到 AppID, 能登录 mp.weixin.qq.com 后台。

> 临时方案: 还没注册也能跑 —— 微信开发者工具支持「测试号」和「游客模式」。导入项目时 AppID 选「测试号」即可全部功能本地预览; 注册后再替换成正式 AppID。

---

## 第二步: 下载并安装微信开发者工具

1. 打开 **https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html**;
2. 下载 **「稳定版 Stable Build」** → Windows 64 位(你的电脑是 Windows);
3. 安装(默认下一步即可) → 打开 → **用微信扫码登录**(必须是第一步注册小程序用的那个微信, 或者被加为项目成员的微信)。

---

## 第三步: 导入项目

1. 开发者工具首页 → 点 **「+」→「导入」**(不是"新建");
2. 填写:
   - **目录**: 选择你电脑上的 `C:\Hackthon\AI4Climate\miniapp` 文件夹(注意是 miniapp 子目录, 不是仓库根目录);
   - **AppID**: 填第一步的 AppID(或点「测试号」);
   - **项目名称**: 随便填(如 "梅家坞茶园微气候");
3. 点「导入」→ 工具会自动编译, 左上角出现模拟器(手机画面)。

**完成标志**: 模拟器里出现"大盘"页面(数据可能显示"加载失败", 正常 —— 下一步配置服务器地址)。

---

## 第四步: 配置服务器地址(关键一步)

小程序需要知道后端在哪里, 有两个场景:

### 场景 A: 本地调试(推荐先跑通这个)

1. **先在你电脑上启动后端**: 打开终端, 运行
   ```
   cd C:\Hackthon\AI4Climate
   python agent/server.py
   ```
   (看到 `Uvicorn running on http://127.0.0.1:8000` 即成功, 保持这个窗口开着);
2. 回开发者工具 → 点顶部 **「详情」→「本地设置」** → 勾选 **「不校验合法域名、web-view(业务域名)、TLS 版本以及 HTTPS 证书」**;
3. 在模拟器里点底部 **「数据接入」** tab → 服务器地址栏填 `http://127.0.0.1:8000` → 点「保存并测试」;
4. 切回「大盘」tab → 下拉刷新(鼠标在模拟器里从上往下拖) → 应该看到实时气温和预报曲线。

**完成标志**: 大盘显示气温/湿度/72h 预报曲线; 数据接入页显示"服务正常 · 地图功能可用"。

### 场景 B: 连云端后端(团队共用)

在 Railway 项目 → Settings → Networking → **Generate Domain** 生成域名后, 把地址填成
`https://你的项目.up.railway.app`, 保存即可(无需勾选"不校验"的步骤)。

### 场景 C: 手机真机连你电脑的后端(局域网, 演示最常用)

手机上的 `127.0.0.1` 指手机自己, 连不到电脑, 需要改用电脑的局域网 IP:

1. 电脑和手机连**同一个 Wi-Fi**;
2. 电脑上按 `Win + R` → 输入 `cmd` → 运行 `ipconfig` → 找无线网卡的 **IPv4 地址**(形如 `192.168.1.23`);
3. 后端改成监听所有网卡(默认只监听 127.0.0.1):
   ```
   cd C:\Hackthon\AI4Climate
   python -m uvicorn agent.server:app --host 0.0.0.0 --port 8000
   ```
4. 第一次运行时 Windows 防火墙弹窗 → 勾选「专用网络」→ **允许访问**;
5. 手机小程序 → 「数据接入」页 → 服务器地址改成 `http://192.168.1.23:8000` → 「保存并测试」;
6. 手机上必须打开调试: 右上角「···」→ 打开调试(否则 request 和地图地形图都会被域名校验拦下)。

> 换 Wi-Fi/热点后 IP 会变, 演示前先确认一次 `ipconfig` 的地址与小程序里填的一致。

## 第五步: 在电脑上验收四个功能

按 tab 顺序各点一遍:

| tab | 验收点 |
|---|---|
| 大盘 | 4 张指标卡有数字; 预报曲线画出 P10–P90 区间带; 风险行显示"无霜冻"等胶囊; AI 建议生成文字 |
| 农事助手 | 点快捷问题("会不会有霜冻?"), 几秒后助手给出回答; 手动输入问题也能答 |
| 地图选点 | 地图默认是**地形图**(彩色高程+山体阴影, 不是街道图); 左下角可切「地形图 / 卫星图 / 街道图」; 点地图任意位置 → 出现定位针 → 下方显示海拔/坡度/坡向; 点「运行微气候模型」等 3–10 秒出结果(视野自动收缩到预测格网, 底下叠 72h 霜冻图层); 点「AI 解读这个点位」会弹窗给解读 |
| 数据接入 | 服务器地址显示"服务正常"; CSV 上传流程见下方提示 |

**CSV 上传怎么测**: 小程序无法浏览手机本地文件, 只能选"微信聊天文件"。测试方法: 把 `training_data/open-meteo-30.19N120.11E180m.csv` 发到自己的微信"文件传输助手", 然后在数据接入页点「选择 CSV 上传」→ 从聊天记录里选这个文件。上传成功后大盘的预报会立刻使用传感器数据(状态条会显示"传感器实测 + Open-Meteo 互补")。

## 第六步: 手机真机预览(体验版, 发二维码给团队)

1. 开发者工具右上角点 **「上传」** → 填版本号(如 `1.0.0`)和备注 → 确定;
2. 登录 **mp.weixin.qq.com** 后台 → 左侧「管理」→「版本管理」→ 找到刚上传的「开发版本」→ 点 **「选为体验版」**;
3. 左侧「管理」→「成员管理」→「体验成员」→ 把团队成员的微信号加进去(最多 15 人);
4. 回「版本管理」→ 体验版二维码 → 发给团队扫码即可在手机上打开。

**手机上如果显示"数据加载失败"**: 大概率是域名校验。在手机打开体验版 → 右上角「···」→ 打开调试 → 重新进入即可跳过域名校验(仅体验版/开发版有效)。

---

## 第七步(可选): 正式发布

正式版有平台硬约束: **request 合法域名必须是 HTTPS 且已完成 ICP 备案的域名**。Railway 分配的 `*.up.railway.app` 域名无法备案, 因此正式发布需要:

1. 购买一个域名(阿里云/腾讯云, 约 ¥30–60/年)并完成 ICP 备案(约 2–3 周, 免费但需身份材料);
2. 把这个域名 CNAME 解析到 Railway 服务(在 Railway → Settings → Networking → Custom Domain 添加);
3. mp.weixin.qq.com 后台 →「开发」→「开发管理」→「开发设置」→「服务器域名」→ request/uploadFile/downloadFile 合法域名都填你的备案域名;
4. 回「版本管理」→「提交审核」(需填功能说明; 我们的小程序属"生活服务-气象信息类", 一般 1–7 天出结果);
5. 审核通过后 → 点「发布」→ 正式上线。

> 比赛阶段建议先用体验版演示; 正式发布留到赛后按上面流程走。

## 常见问题

| 现象 | 解决 |
|---|---|
| 大盘一直转圈/加载失败 | 后端没启动(场景 A)或地址填错; 在数据接入页点「重新检测」看报错 |
| 地图页点了没反应 | 地图需要几秒加载; 若报"点位查询失败"检查后端日志 |
| 曲线画不出来 | 确认能拿到预报数据(大盘有数字); canvas 需在真机确认渲染 |
| 上传 CSV 失败 | 确认文件是 UTF-8 编码的 CSV 且含"时间+气温"列; 参考数据接入页的格式示例 |
| 手机上图片(叠加层)不显示 | 叠加层 PNG 需要 HTTPS 域名; 本地调试时用开发者工具预览 |
| 修改了后端代码 | 本地重启 `python agent/server.py`; 云端 git push 后 Railway 自动重新部署 |

## 需要更新的地方(如果后端重新部署了)

- 数据接入页的服务器地址(存本机, 换设备要重填一次);
- `miniapp/app.js` 第 2 行的 `DEFAULT_API_BASE`(如需改默认值);
- 正式发布时: `miniapp/project.config.json` 的 `appid` 换成正式 AppID(开发者工具导入时填过就不用改)。
